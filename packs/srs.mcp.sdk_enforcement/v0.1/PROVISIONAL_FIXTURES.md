# Implementation fixture status

The `normative/` directory is a permanent byte-identical copy of the standard-layer WP2A vectors. It is never replaced.

Implementation-generated fixtures supplement the normative set under `implementation/`. An implementation fixture remains provisional unless:

1. its bytes were generated by the implementation's real governed code path;
2. it carries a discoverable `expectations.json`;
3. the expectations declare the exact profile, keyring, receipt set, complete nine-verdict vector, and expected failure codes; and
4. the generic implementation-fixture test verifies every declared value and proves through a negative control that mismatches fail.

Those conditions are satisfied in this tree for the DAGR FastMCP implementation fixtures. The generic discovery test covers every `packs/*/*/implementation/*/expectations.json` file, rejects missing or unknown verdict keys, and verifies the complete vector for each listed receipt. The provisional status is therefore closed on this tested basis.

The same conditions are satisfied for the DAGR MCP first-run capture fixtures under `implementation/dagr-mcp-first-run/`. Their bytes come from the producer's real governed code path in capture mode (fixed signing identity, injected clock), which makes them byte-reproducible; per-entry digests and the generator commit are pinned in `implementation/dagr-mcp-first-run/manifest.json` and asserted against the fixture bytes. That set is signed by a different issuer than the FastMCP set, so it carries its own keyring and its own `expectations.json`. It completes the pack's journey from admitted-only to admitted + refused + mutation, recorded in `proof-pack-manifest.json`.

The refused admission fixture is declared `signature_valid: true` with no expected failure codes. That is deliberate: a refused admission receipt is a valid receipt, and verifying it passes because it is authentic evidence that a refusal occurred. Refusal is not modelled as a verification failure. Non-execution of the native action is not a verifier verdict at all — it is the producer's observed fact, recorded in `side_effects.json`, whose booleans are not authored here.
